# 星球交互、双向物流与微缩收藏提案

2026-09-22。回应第一人称交互、背包放置、星球回收、微缩作品、破坏地形与无限世界的讨论。本文件主要为后续设计，未实现的能力不计入发布版本。0.21预览现已增加约1公里探索区、分块地形加载和附近野生植被采集；仍没有通用对象交互、地形编辑或回程货物。最新边界见[V0.21预览](V0.21-PREVIEW.md)。

后续用户确认多时代、组织、人物性格与控制规模的方向，并要求继续扩大地图与补充生命。调研和分期建议见[材料与多时代沙盒](research/MATERIAL-TIMELINES-RESEARCH.md)；本文件的256米候选已由约1公里探索预览替代，材料因果仍须从四个起始试验区扩展到局部环境。

## 1. 核心循环

浮岛合成与工厂加工 → 携带材料、器件到星球 → 改造具体地点、种植、饲养、搭建 → 获得自然原料、生态样本和自建作品 → 带回浮岛研究、制造、装饰 → 解锁新的干预方法。

浮岛擅长提纯、合成、制造与研究。星球提供自然环境、混合原料、生物与可持续经营的土地。两端库存使用同一物品身份/事务规则，位置不同不产生第二份资产。金币用于人员、设备、加工服务等经营环节，投放直接消耗已有物品。

普通资源也能往返；用运输容量、提纯损耗、加工能耗和订单吞吐控制经营节奏。世界扩大不自动扩大市场收购量。实验副本继续隔离资产，不能把复制出的资源或建筑提现到主世界。

## 2. 第一人称对象交互

视线对准近处对象时显示轮廓、名称和1个主动作；桌面E/触屏操作键执行，展开菜单显示其他动作。建议初始可操作距离3米，作为可调游戏参数。

|对象|默认动作|展开动作与反馈|
|---|---|---|
|动物|观察个体|喂食、命名、引导、使用运输笼；显示饥饿/健康/谱系与正在做什么|
|作物|查看生长，成熟时收获|浇水、留种、移栽；生长或缺水反馈出现在对象旁|
|土壤|持种子时播种|采样、挖掘、填土；显示落点与可用种子数|
|河水|取样|用水罐取水/补水，布置进水口；留下实际数量和采样位置|
|围栏/门|开关|修理、拆卸、打包；动物路线随可达性变化|
|设备|查看工作状态|补给、接管线、替换组件、停机、回收|
|自建作品|查看名称|选择整体、保存蓝图、制作微缩件、原件装箱|

底部快捷栏先6格，切换观察、种植、工具、建筑块和器件。长按破坏仅在工具/拆除模式生效；拖动画面永远只转镜头。触屏移动/转向与右侧动作键分工，避免回看动物时误挖地。距离、遮挡、目标存活与库存资格由模型最终校验。

摆放使用半透明预览、旋转、吸附开关与占地/连接提示。确认后扣真实库存；失败不扣。结构构件、设备和纯装饰共用同一放置流程。上帝视角批量布置，第一人称精细施工，均调用相同事务。

## 3. 背包物品如何使用

|类别|星球用途|准入规则|
|---|---|---|
|水样、氧气样品|小范围试验|现有白名单保留；样品用量与作用范围明确|
|装罐水、气体补给、营养供料|补水、供氧、施肥|工厂放大为有数量的产品，保留来源批次；气体需要相应容器/投放工具|
|木石土、玻璃/金属构件|墙、桥、围栏、温室外壳等|形状和材料分开，同一种墙可替换材料；用料数量明确|
|泵、过滤器、太阳能组件、蓄电池等|组成有供能/耗材约束的小系统|依赖相应加工配方、规格和连接，不因摆出来就永久生产|
|种子、饲料、生物样本|种植、饲养、保种与移栽|产地、个体/谱系或批次身份保留|
|玩家未知结构|雕塑、结构展示与研究样品|允许可视化/收藏；未知性能不被填成零或自动通过功能用途|

功能判定分两步：用途要求 → 材料在该条件下有无合格性质证据。已有家族模型范围内的材料可以参与对应用途；未知作品可先艺术创作、带回研究或在隔离假设试验中比较。科学家解锁方法和验证路径，等待时间本身不生成真实物性。

当前材料效果按四区域结算。下一步需要把水分、营养等改为较粗的局部环境网格，再连接相邻格；视觉方块不必每格运行化学。先实现定向灌溉/供氧/遮荫覆盖范围，再增加水流与扩散。任意倒下一颗分子不会使整片地形变成这种物质。

## 4. 回程与微缩作品

星球回程分为原料/样本、蓝图、实体作品三种，不新增独立赚钱货币。土壤、原木、矿样、种子与作物带回后可研究或加工；矿样是混合物，化验和提纯后才能成为相应材料库存。作物可经加工成为岛上补给，不能自动等同于已有泡面成品。

建议增加浮岛“微缩展台”：玩家在星球上搭温室、小桥、磨坊或花园，框选后看整体预览、体积、重量/装箱成本，放到浮岛空地上成为可旋转的立体收藏。保存名字、地点、季节、作者和使用过的材料。

两条明确操作：

- **制作微缩模型**：复制外观蓝图，消耗岛上制作材料，保留原建筑。可有风车转动等展示动画，不复制原建筑的产能。适合第一期。
- **收纳原件/活体生态舱**：后续的科幻运输能力。原件、个体与库存从星球移出，打包后成为唯一物品，在浮岛展开才继续运行；移动位置不重置年龄/剩余补给，不产生复制。收纳前断开外部管线并说明哪些功能将失去供给。第一期活体舱仅限一个小水池/花圃及少量生物，明确尺寸/个体上限。

蓝图可以保留与复制，实体和其中物资只能存在一处。微缩本身是游戏的科幻表现，不标成真实物理技术。展示模型、活体舱、生产设施有清晰标识；模型收藏价值来自玩家作品及经历，功能设备继续需要供料与能源。

建议让博士休息时参观作品、给作品留观察记录，稀有样本解锁研究问题；不让摆满重复纪念品无限叠加全局收入。

示例首个完整故事：带水箱/玻璃构件到草甸 → 搭花园并引水 → 种植收获 → 选一块成熟花圃制作玻璃罩微缩作品 → 浮岛摆放 → 用剩余作物加工补给。后续把园艺作品放进活体生态舱，继续保种和观察。

## 5. 可破坏世界

目标支持挖土、砍树、采石、拆建筑、垒墙和改道，再扩展洞穴、桥下空间与悬空建筑。破坏与采集有实际后果：移除格子/对象后才产生对应物品，回填/搭建消耗库存；采伐影响遮荫，沟渠改变可达性和后续水路，拆门改变动物通行。

目前河湾由每个水平位置的一个高度生成。洞穴/上下叠层需要三维方块数据，不能只从渲染网格上删面。建议引入分块体素存储，形状与材质分离，只有被编辑的块与邻接边界重建几何/碰撞；不为每个方块建立独立场景节点。

首期只开放有限垂直层的土石挖填与简易构件搭建，数据结构保留未来洞穴空间。水流先用有限水量、粗网格连接与水位模型验证沟渠/池塘；暂不承诺真实流体。支撑和损坏先采用可解释的简化规则，不实时模拟所有建筑力学。

## 6. 广阔星球与无限探索

建议主星球是持久、有限但很大的地图；世界数量可以扩展。一颗球的拓扑与无限平面不同。近处连续步行加载区域，全球地图负责定位和远途旅行。当前已用半径512米的平面探索区验证加载与持久栖地，后续大小仍由手机实测预算决定，不按版本持续翻倍。它不是完整球面，也没有地下体素。

如果用户更偏好一直朝一个方向探索，可单独做程序生成的无尽大陆模式，其地图表达与主星球区分。它仍受存储容量和数值范围约束，不能承诺数学上的无限或永不增加的存档。

未探索地形由种子/生成器版本/区块坐标决定；保存用户修改、对象状态、资源开采与必要的生态摘要。返回已经挖掘的地区不能重新刷矿或复制生物。冻结既有世界生成器版本，升级不随意重排玩家家园。

近处运行个体活动；远处以较低频率推进区域人口、资源和设施账本，回到近景时从原身份及摘要恢复，不复制人口、不把离开当作生态重置。离线/远区的演化是近似模型，要说明精度和时间上限。最早切片继续使用当前离开即暂停规则，远区演化单独验收。

## 7. 低耦合实现边界与分期

|模块|责任|
|---|---|
|InteractionResolver|目标、距离、遮挡、上下文动作；界面只展示返回结果|
|InventoryTransfer|同一物品在工具箱、放置对象、运输箱、展台之间的唯一转移|
|Placement/WorldObjects|带ID的实际位置、朝向、连接、物品快照；旧区域建筑迁移到确定位置|
|TerrainChunks|生成、方块修改、差量保存与局部几何/碰撞更新|
|EnvironmentGrid|局部条件与邻接输运，不受渲染帧率驱动|
|Specimen/Blueprint/Packing|样本来源、作品选择、外观模型与原件收纳的不同账本|
|WorldStreaming|加载/卸载、生态摘要与存档版本，不负责发奖励|

第一批：对象准星/E交互、手机动作键、快捷栏、实体点位放置/回收、从真实库存取水/播种/喂食/开门。验收玩家可在同一片河岸走完一次种植、收获和放置过程。

第二批：自然采样、回程箱、土石挖填与简单搭建；同时铺设分块数据基础。验收采集/搭建/回收和重载不吞物或复制。

第三批：自建作品框选、蓝图与可摆放的微缩模型。验收玩家自己搭的花园能摆在浮岛，而非预制奖励换皮。之后做活体生态舱。

第四批：分块扩展地形、生物群落和远区摘要；再评估洞穴、无尽大陆。验收大地图的乐趣密度与手机性能，避免先生成大片无事可做的土地。

## 8. 技术依据

- [Godot SurfaceTool](https://docs.godotengine.org/en/stable/classes/class_surfacetool.html)：支持从数据生成网格，可用于编辑后重建局部地形；本项目现有视图已用此机制，三维地形状态仍需新建。
- [Godot大世界坐标](https://docs.godotengine.org/en/stable/tutorials/physics/large_world_coordinates.html)：大坐标会损失精度；双精度有性能/内存成本，移动端需要谨慎。分区域坐标/按需加载是本项目的工程建议，不等于引擎自动提供无限世界。
- [Godot批量实例绘制](https://docs.godotengine.org/en/stable/tutorials/performance/using_multimesh.html)：批量绘制可减少开销，但整批对象共享可见性，应按区域拆分，而不是一批画完整颗星球。该教程注明尚待4.7版本全面复核，具体实现仍以项目性能测试为准。

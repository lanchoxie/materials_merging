# 0.13 · 河流记得你投下的东西

2026-09-19。材料产品开始影响连通的上游、湿地和河口。藻类增长、残体分解、耗氧、鱼群迁移和底栖损失形成有延迟的过程。玩家可以控源、改道、过滤、植被缓冲、收割和临时供氧；不同方法处理不同问题。

## 试玩路线

1. 广场邮箱 → 材料试验星球 → 顶部「河流湿地」。领取合作后，选择晚泥盆纪河口林地或晚石炭纪沼泽森林。初次开启会暂停，方便布置。
2. 先选河口，点击「观察30秒」逐段推进。默认营养源有限，但持续输入会在数分钟内造成藻与碎屑积累、下游低氧；鱼向外缘转移，无法迅速离开的底栖群体承受损失。
3. 下方「水域成品…」选择过滤机、滤盒、缓冲带或收割箱。主世界先在生产工坊提交同批2份水样获得教程资格，再采购对应组件并制作；水样资格不等于测出了滤材性能。
4. 过滤机需要单独的滤盒和动力。把两种产品先后拖入水域，可看见转子工作与截留物积累。饱和或动力耗尽会停机；更换旧盒把截留物转入本世界封存账本。
5. 缓冲带增加植被吸收空间。选择「下次收割：植被」再投放收割箱，作业船开始有限收集。已经开工的收割不会随下一单偏好改变目标。
6. 旧版供氧器、补给盒、导热芯也可投入水域。上游/湿地采用窄槽支架，河口采用轻量支架；装不了的构件不会被扣除，换下的构件保留来源退回库存。
7. 在观察栏下方复制当前河流，或创建另一个时代的实验。两个同起点副本可同步推进；不同年代的初始条件不同，不能作为严格同条件对照。历史滑块只改变显示，不回滚库存或实际生态。

主世界使用真实制造的成品。实验A/B有独立的有限配给，可重置；虚拟产品和封存物不会流回浮岛出售。任一时刻只详细显示一个世界，离开观察界面不追赶离线生态灾难。

## 两段可以改变的故事

**清水也会再长藻。** 上游机械过滤让颗粒减少，但溶解营养仍可顺流而下。默认晚泥盆纪模型中，只过滤上游的河口藻量甚至可能高于未过滤分支。玩家需要联合控源、缓冲和收割，不能以水的透明度判断饮用安全。

**救急以后还要善后。** 在60秒关闭上游营养输入，河口仍可能在180秒左右低氧，因为已有生物量继续分解。额外投放一盒氧气可以减轻这段压力；之后仍需让残体减少。鱼可能回游，残存底栖群体恢复较慢；已死亡群体不因切换页面或重开通道而复活。

这些时间和阈值是当前平衡版本的游戏参数。玩家可以观察原因、做同条件对照；不能把结果解读成真实河流的治理剂量或生物致死浓度。

## 科学来源与模型边界

[NOAA营养污染概述](https://oceanservice.noaa.gov/facts/nutpollution.html)和[缺氧区说明](https://oceanservice.noaa.gov/facts/deadzone.html)支持营养过量、藻类、分解耗氧以及可移动动物离开的定性方向。这里用一个固定步长教学模型表达这些关系，没有复制真实物种参数。

[EPA水处理技术概述](https://www.epa.gov/sdwa/overview-drinking-water-treatment-technologies)用于区分处理目标；[EPA人工湿地概述](https://www.epa.gov/wetlands/constructed-wetlands)用于植被、土壤和生物过程协同处理的概念参考。机械滤盒不去除全部污染物，水域没有饮用安全认证。

[NPS泥盆纪介绍](https://www.nps.gov/articles/000/devonian-period.htm)与[宾夕法尼亚世介绍](https://www.nps.gov/articles/000/pennsylvanian-period.htm)提供鱼类、林地与沼泽植被的美术方向。两个程序化场景是古生态灵感沙盘，浮岛设备由玩家带入；不复原古代全球气候、具体物种组合或真实年代时长。早期氧敏感菌的玩法仍在上一章隔离试验舱内，不能据此说泥盆纪或石炭纪生物普遍怕氧。

溶解营养、藻、植物、碎屑、滤盒截留物都采用同一种游戏营养当量，只追踪其营养份额；不声称这些池是完整生物质量，也不是实际N/P比例、kg或mg/L。账本保持：初始总量＋外部新增＝当前各池＋输入舱剩余＋域外流出＋封存废物。氧另用0—100指标，鱼用固定群体权重，画面只显示有上限的代表模型；没有逐条鱼的完整生命模拟。

目前不模拟季节、光照昼夜、盐度、分层、食物网或完整碳循环。缺氧时降低好氧分解速率，未额外捏造未知的厌氧代谢产物。植物吸收有容量且会返还营养，不能无限吞掉污染。

## 模块、调参与存档

- `planet_watershed.gd`：确定性的输运、生物响应和守恒校验，不操作金币或渲染。
- `planet_watershed_view.gd`：连通水域、两套植被、代表鱼群、过滤与收割动画。
- `planet_watershed_panel.gd` / `planet_watershed_chart.gd`：操作、曲线和只读回看。
- `planet_program.gd`：复用唯一的资格、采购、制造与部署事务；`planet_worlds.gd`负责副本、基线和时间。
- `data/planet_watershed.json`：流速、生长/死亡/耗氧、容量、初始群体、时代和历史上限；`planet_balance.json`单独管金币、工时与配给。

外层存档14、星球格式4。旧版新增休眠水域，保留工业订单、已安装组件、资格、成品、旧生态及历史。开启新章节不能覆盖之前实验的组件基线或预算。修改初始总量、守恒定义、设备容量或硬性适配条件时，要增加模型版本与迁移，不能只改配置后拒绝玩家已有存档。

每世界最多保留120条水域快照，旧生态历史也保持其上限；只复制当前显示需要的状态，不在刷新画面时重复复制整段历史。树木静态合批，鱼、藻斑与动画对象有固定上限。

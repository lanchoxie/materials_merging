# 地球独立评审：材料怎样改变生态与居民行为

评审日期：2026-09-19。状态：开发前设计建议，未实现。已阅读 `../EARTH-DESIGN.md` 与 `EARTH-CORE-REVIEW.md`。本文只审视生态、时代内容与可见反馈；数值示例均为待试玩校准的游戏参数，不是古生态预测。

## 1. 核心意见

地球值得玩的地方，是**同一份产品在不同地方改变不同的限制条件，生物和居民随后自行响应**。材料不直接增加“文明值”；氧气也不是通用补血药。更可信、更省制作量的链是：

**材料证据 → 有明确功能的产品 → 改变局部环境或基础设施 → 某群体的需求被满足/受损 → 迁徙、生产、扩建或冲突 → 新需求。**

保留旧方案的水箱教学，但它只证明部署技术能跑通。下一切片至少需要一组“相同投入、不同结果”的可视化对照，否则仍不足以证明新目标中的开放生态玩法。优先选择两个封闭观察池：一个缺氧的有氧生态群、一个以氧敏感厌氧微生物为主的群落。它们共用几何、管线和微生物贴花，制作成本远小于先做完整恐龙生态。

## 2. 必须纠正的科学关系

1. **“古代加入氧气会致命”不能覆盖泥盆纪、石炭纪、白垩纪。** 氧敏感微生物受氧化环境冲击的教学情景，更适合独立的早期微生物序章。泥盆纪海洋已有需要氧的动物；海洋内部仍可以有贫氧或缺氧区域。Smithsonian 的早期生命资料支持早期氧化使某些不耐氧微生物的环境恶化，但不支持给所有古生物设一个统一死亡开关。[S1]
2. 大气氧分压、水中溶解氧、沉积物内部氧环境分别储存。H₂O 分子中的氧不能直接当成鱼能呼吸的溶解 O₂；把水倒进缺氧池不会按水里的氧原子数给鱼补氧。[S2]
3. 同一种物质的后果依赖剂量、暴露时间、位置和生物类群。采用分区、渐进胁迫和恢复过程，不采用“放置一瓶，整球立即清空”。具体响应曲线须明确是游戏标定。
4. 营养盐过量的有趣代价不是立即毒杀，而是生产者增殖、遮光、有机物累积及分解耗氧，再影响消费者。即使画面早期变绿，后续也可能恶化。[S3]
5. 不把大气氧增加直接写成所有虫子即时变大。巨型节肢动物与氧环境的关系是研究议题，还受谱系和生态条件约束；游戏用预设类群与栖息条件，不捏造进化公式。[S4]
6. 热导率、电导率、孔隙率等工程性质不能推导出通用生态毒性。新材料的浸出、暴露和生物相容性需要独立证据；未知时只允许封装使用或受控实验，不能凭“材料等级”判断能否撒进海里。
7. pH 不是线性刻度。首版没有酸碱平衡模型时，使用注明游戏抽象的“酸化压力”，不要把混合两份水的 pH 直接平均后称为真实结果。[S5 支持 CO₂ 与海水化学的方向；具体求解仍需后续模型]

泥盆纪已有鱼类多样化和早期森林的内容，可由 NPS 资料作为科普卡依据。[S6] 白垩纪的植被变化、授粉与动物关系由 NPS 内容支撑，但具体模型名单仍应按地层/地区审定。[S7] 地质边界年代另统一使用同版本 ICS 表；上述官方科普页的旧年代不应直接混入主数据库。

时代模板可以独立开启。跨时代投送高科技是明确的“假设实验”，居民能否使用依赖培训、配套和维护，不必假装符合真实历史。地质场景的生态时间与人类场景的工作时间分别定义；不做从熔岩连续等待数亿年才到现代的强制流程。

## 4. 十六个具体场景：玩家看得见的因果与补救

以下是游戏设计，不是数值预报。每条都至少需要一个可逆的调节动作；保留“观察但不干预”的选择。

|场景与投入|第一层作用|生物/居民随后做什么|画面与补救|
|---|---|---|---|
|1. 氧敏感微生物池接入供氧设备|暴露区氧环境改变|敏感群覆盖减少，耐氧群在适合区域扩张；深层庇护区保留|两种菌席斑块边界移动；可停供、分隔池和保留无氧微环境|
|2. 缺氧鱼湾接入同一种供氧设备|局部溶解氧恢复，设备持续耗能|可移动鱼群先靠近恢复区，随后才扩散；未恢复区仍空|鱼群方向、气泡、泵动作改变；修复电源、分配曝气位置，避免全池瞬时恢复|
|3. 热浪时只补氧却不处理热源|氧输入改善一项约束，温度胁迫仍在|热敏鱼仍寻找合适区域，无法迁移时群体下降|冷水通道与鱼群聚集可见；改散热、通水或遮阴，而不是无限堆瓶|
|4. 河口给太多营养制剂|生产者先增加，随后死有机物和耗氧负担上升|初期鱼食增加，后期底栖群和鱼群受影响|绿水先出现，之后底部沉积和逃离；减源头、分流、处理有机物，单靠补氧成本高|
|5. 上游建立精准肥料供给|满足作物缺乏的养分并限制流失|居民提高粮食储备、腾出部分劳动力修桥|农田先变密，谷仓变满，项目排队增加；错误季节施用造成浪费，不能直接换时代|
|6. 向海湾持续增加 CO₂ 负担|逐渐改变碳酸盐化学相关压力|部分钙化类群生长/维持受限，依赖它们的消费者改变觅食|壳类覆盖和补充速度下降；控制输入并观察延迟恢复，不使用“氧气中和酸”按钮|
|7. 淡水扩展到有盐度偏好的浅海区|水量增加同时改变盐度|类群分布变化，有的退、有的进|淡水羽流、鱼群与岸边斑块移动；选择排放位置、缓慢供水或恢复连通|
|8. 白垩纪旱季投放水箱建设水坑|局部饮水条件改善|草食群迁来，肉食群追随；周围植物受集中啃食|足迹、迁徙线和小群动画；分散水源以减轻过度集中，不让一箱水喂整个大陆|
|9. 为水坑建直达运输路|补给更可靠，但部分路线形成通行障碍|动物绕路，居民运输变快|路上车辆与绕行足迹；建涵洞或生态通道，而不是纯粹加减一个生态分|
|10. 给聚落耐腐蚀且已验证的管件|漏损和停水维护频率降低|供水工减少抢修，居民提出浴室/作坊用水项目|漏水喷溅减少、施工者转移；需求增长可能重新造成缺水，仍须扩供|
|11. 给聚落高导电组件与绝缘配套|具备已解锁的局部配电能力|工匠优先接近线路建作坊，家庭申请灯具|电线逐段亮起、工作时段变化；无发电或无维护时只能保留待用设施|
|12. 高热值燃料进入成熟供热设备|可用热量增加，伴随设备规定的排放与维护|寒冷时居民少花时间取暖，工场更稳定|炉火、暖屋和运料线；空气质量差时居民要求烟气处理/迁址，不把高热值等同全面最优|
|13. 同一高导热材料分别做散热片和保温层|散热片有利于传热；保温应用可能不匹配|计算站/机器运行更稳，但错误保温让供热压力上升|散热片流动/热色减弱与房屋失热对照；可拆换，不直接由单一导热值计算整机性能|
|14. 给城市更耐久的储能组件|有足够充电供给时，减少特定短时中断|居民保留夜间服务，关键泵更少停机|夜间局部灯网、泵与列车恢复；充电缺口长期存在时仍耗尽，不能凭电池产能|
|15. 通过测试的新吸附材料进入合格滤芯|改善指定污染物的处理并逐渐耗尽容量|居民扩大饮水服务，维护者定期换芯|滤芯渐变、清污双管和收集废料箱；对盐分/病原没有证据则仍需其它处理环节|
|16. 工业城市把有限耐热合金用于公共设备或军备订单|两个项目争用同一产线与运力|不同居民群体支持不同计划，后续申请与供给改变|医院/供电维修和车辆订单不同施工场面；结果是资源分配故事，不宣称某历史战争必然胜败|

1–4 可共用同一观察池，是最值得优先实现的核心试验。第 13 条是很好的“高属性并非越高越好”材料教学。第 10–16 条提供居民自治和材料研发之间的桥梁。

## 5. 生物不逐只算：群体计算，代表个体表演

每个区域保存少数 `PopulationCohort`：类群 ID、生物量/游戏群体规模、生活阶段、食物类别、迁移能力、环境响应配置、胁迫累计量、恢复记录。屏幕上的一条鱼或一只恐龙是群体的代表；其离开屏幕不会删除真正种群。

每一类群的适生条件是独立配置：温度、可用食物、氧环境、盐度、栖息地和必要的伙伴关系。先取限制条件，再应用环境胁迫；高食物不能抵消致命缺氧。具体响应曲线及速率是游戏参数，只能称“该教学情景中的响应”。没有对应证据时，不展示真实物种的精确致死浓度。

将延迟写进过程，避免骤变：

- 适生性变差后先减少繁殖/觅食，再累积胁迫；可迁移者沿连通区域移动，固着群无法迁移。
- 死亡形成可分解有机物；不能凭空消失并直接重置生态。
- 压力解除不瞬时满血，恢复受剩余种群、食物、幼体来源和连通性限制。
- 捕食用群体间有限流量；不为每对恐龙做追逐寻路，也不让一个动画击杀决定整群数量。
- “灭绝”区分本区消失与所有副本全部消失；保种库/上游迁入可作为补救，代价清楚且不自动无限复活。

第一次实现最多 4 个群体：氧敏感微生物、耐氧/需氧微生物、生产者、示意鱼群。早期池只启用前两者；鱼湾启用后几者。避免说这四者构成一份精确的古生态复原。

## 6. 小人会改造世界：基于需求的项目队列

人类出现后，在生态层之上增加地区项目规划。居民先识别短缺，再从已经掌握的配方、设施和材料中选择方案。例：饮水不足 → 比较修管、扩泵、处理水源三个可用项目 → 预约材料与工位 → 运输施工 → 服务范围扩大 → 新居民或工场提出新需求。

每个候选项目以可解释的因素排序：紧迫性、预计受益群体、现有知识、输入是否齐全、运送距离、维护负担、地区偏好。只让 1–2 个主要因素出现在头顶泡泡中；完整比较在项目卡查看。玩家可以批准预算、禁建区域、指定重点服务，居民负责小范围选址与排队，不擅自花尽浮岛钱包。

居民群体也有不同诉求：农户要水与肥料，工匠要供电和工具，居民要住房与空气，管理者要可靠储备。性格影响偏好和行动节奏，不能改变材料实测性质。项目争议用可选择的安排表达，不把任何阶层写成永远正确或永远自私。

限定自治规模：每个区域同时最多一个主要工程、少数维护任务；既定区域槽位加短路径连接。建筑不会随机无限蔓延。玩家新材料只有通过对应应用验收，才进入居民候选列表；未知材料可先进展馆或受控试验设施，居民会提出“希望测试能否替代现有滤芯”一类研究需求。

## 7. MVP 状态与计算顺序

建议第一轮用两个封闭池、各 3 个区域，复用一个底座。活跃世界总共 6 个水区域，另有一个公共背景大气记录。每个池以同起点快照复制，能够暂停、恢复、对照投放。玩家由此先理解“环境决定后果”，再进入大时代关卡。

|层|首版状态|暂不做|
|---|---|---|
|区域水环境|水量、温度、溶解氧量、营养负荷、有机物负荷、光照/浑浊代理、与邻区连接|全流体、真实天气场、全球海洋环流|
|气体与产品|氧气产品库存、设备供给速率、用能、开关、排气/溶解分配记录|整颗星球的大气化学网络|
|生态|最多 4 类群的规模、适生性、胁迫、迁移、死亡分解|逐只代谢、基因组、自由演化出新物种|
|场景流程|投放、运行、观察采样、对照、一次性事件|一条强制历史线、无法暂停的巨灾|
|表现|水色/贴花/气泡、少量鱼群与菌席、箭头式连接、设备动作|每种材料单独环境特效与模型|

固定逻辑步长与同条件事件种子保证副本比较；画面插值可以高频，群体计算低频。每步建议顺序：读取有版本的投送命令 → 设备消耗/产出 → 邻区交换 → 光合作用/呼吸/分解等已启用过程 → 生物胁迫与迁移 → 事件快照。区域间交换先统一计算再统一提交，避免遍历顺序让上游多移动一次。

溶解氧可以存总量并由水量换算浓度，但必须先统一质量/体积单位。第一轮若仍使用“标准箱”等游戏单位，就把池内氧状态显示为教学指标；不要把未标定的数值印成 mg/L。引入真实 DO 时，对照 USGS 方法，显式考虑温度、压力、盐度及设备传质假设。[S8]

```
氧量变化 = 输入溶解量 + 区域净交换 + 光合产氧
          - 呼吸耗氧 - 分解耗氧 - 排出/气液交换
```

这只是记账结构，不是已校准的科学模型。过程参数分清来源模型与游戏平衡；耗用不能超过现有氧量，输出与消耗分别记账。缺氧时降低依赖氧的过程，不允许先算出负氧再随意裁零掩盖质量损失。类群增长同样消耗配置中的食物或营养池，防止无限增长。

生态反馈至少保留两级事件：一是“发生了什么”（鱼向上游迁移），二是可追溯原因（此区氧胁迫持续、邻区更适宜）。点击鱼群能连回对应环境和玩家投放记录。隐藏详细公式不妨碍展示因果。

## 8. 画面与建模范围

MVP 新美术预算建议：一个观察池底座、一套管线/设备外壳、两种菌席材质、一个通用鱼群骨架、三种植物/藻类簇、一个采样标记。水位、颜色、覆盖密度和群体位置承担状态变化。不把屏幕全部染绿代表“污染”，而是按已存在的具体过程展示浑浊、藻团或沉积；清澈也不等于可饮用。

进入地质时代后逐包加轮廓：泥盆纪 2 类鱼与早期树；石炭纪湿地树、海底生物簇、一种代表节肢动物；白垩纪一种草食与一种肉食恐龙加植物变体。相同骨架只做近缘外形变体，避免把所有古生物都套同一个现代鱼模型并标成精确复原。

每个场景只需要 3–5 个“故事镜头”：鱼逃出海湾、菌席扩张边界、恐龙围水坑迁移、居民抬管件施工、夜间街区逐段亮起。小群的行为与场景状态一致，比远景摆满不行动的模型更有说服力。

每帧可见实体设上限、离屏用群体数据；只渲染当前世界，后台世界固定步长低频处理或用户选择暂停。不要承诺每种设备都实时看得见全世界每个居民的路径。性能阈值必须由 Web/Android 实测确认，此处只给内容预算。

## 9. 生态验收建议

- 同样的氧产品对敏感菌池和缺氧鱼湾给出不同且能解释的结果；不按时代名字直接判死。
- 同起点副本在无干预时一致；施肥过量副本出现有延迟的营养—分解—耗氧链。
- 投入纯水不会把其中化学键合氧自动加到溶解氧池。
- 切换世界、保存重开、降帧与加速不会重复扣氧产品，人口不因画面消失而丢失。
- 迁移与区域交换与遍历顺序无关，库存/氧量/水量不为负，不存在设备停电仍长期补氧。
- 有食物但无氧的需氧群不能被“高食物奖励”覆盖限制；不适用已知响应曲线的新材料返回待验证。
- 关闭数值面板后，试玩者仍能指出哪个池发生变化、什么生物在移动、下一步可怎么补救。
- 净水画面清澈不能自动通过全部污染物/病原合同；生态恢复与人类饮用验收分开。

## 11. 建议主计划采用的五个决定

1. 把“早期微生物氧冲击”独立于泥盆纪等场景，取消按时代自动判定氧气利弊的规则。
2. 在第一条水箱技术链之后尽快做两池材料干预对照；这比先堆全部时代模型更能验证乐趣。
3. 环境、生态群体、居民项目、显示个体分别存储；所有时代共享因果过程，不共享一组万能数值。
4. 新材料的生态暴露数据独立于热、电性质；未知作品有展馆/封装外观/受控试验用途，保留继续研发的理由。
5. 对每个未来时代写清代表区域、类群、可用产品与 3–5 个可见故事；不开“任意材料准确预测历史”的承诺。

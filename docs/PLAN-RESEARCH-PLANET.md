# 研发与模拟地球：后续章节方案

状态：早期章节提案，保留作设计沿革。2026-09-19 的现行范围与交付安排见 [多世界地球主计划](EARTH-MASTERPLAN.md)，包含三份独立评审的整合、材料产品链与时代场景。本文的早期区域数量和验收安排已由主计划替代。运行版0.12已实现水箱、副本与氧气生态舱；工业管线、开放生态与完整时代、真实物性预测尚未实现。

## 一、科研要解锁能力，而不是为换一个元素盖章

玩家提出问题、选择结构、调整键长。博士执行装炉、采样、收集和课题实验。教授设计实验流程、带博士提高效率，并主持工艺优化。院士负责新方法、跨体系模型与新的材料结构族；每位院士同时主持一个高级课题。工程师负责建造、维护、物流设施和未来的工业放大。

“氧换成硫”只是新样品任务：预留元素和费用 → 博士沿道路到炉旁 → 装炉 → 开始新批次。它不证明新材料稳定，也不占院士高级课题。换元素与工艺研究、计算任务分开管理。

研发树建议按能力组织：

|阶段|研究问题|团队|实际解锁|
|---|---|---|---|
|浮岛基础|如何避免炉子很快满仓？|博士，可选教授指导|缓冲仓、收集设备|
|工艺优化|怎样提高批次重复性与产速？|教授带博士|过程控制、生产参数槽、批次验收|
|表征方法|如何比较一组不同样品？|教授、博士|参考结构对比与适用范围报告|
|计算方法|新体系的势函数是否可用？|院士、教授、博士|数据集、训练/验证任务、模型有效范围；失败也积累验证资料|
|工业放大|实验样品如何成为可部署产品？|教授与工程师|工厂、能耗/产率、供料与管线|
|新结构族|满足需求的候选结构有哪些？|院士主持，博士筛选|一组有出处的结构候选，玩家继续选择和优化|

0.9先提供缓冲仓（+3容量）、教授主持的过程控制（+15%产速）、并行几何筛选入口三个小规模原型。最后一项目前只解锁批次评分排序，尚不是多物性筛选。院士的完整玩法应等到方法验证、结构族与真实属性数据接入后扩展，不能用大量换元素任务填充。

教授不是多余职位：在初级课题中是可选的效率提升；在工艺研究中是负责人。博士选择做课题后，暂停日常收集与装炉，形成研究进度和运营人手之间的取舍。后续增加手动调派与专长选择，避免全自动分配剥夺玩家决策。

## 二、订单连接样品、产品与下游需求

区分三类访客：供应商卖元素、生活补给与工业原料；采购商买指定样品或指定条件的产品；合作企业提供长期应用课题与测试场地。0.9实现的广场来客主要是采购商，补给由工具箱商店购买，供应商的补货车辆留待后续。

订单分层：名称/配方 → 含哪些元素、结构类别、参考几何 → 有来源的物性区间 → 产品性能与使用条件。前两层可在本地可靠判断；后两层需新增数据或限定适用范围的计算方法。0.9的含氧分子订单检验组成和参考几何，不宣称净水能力。

未来订单示例：“在本次测试温度、pH和污染物浓度下，去除率达到指定范围”“可工作于指定温度的太阳能组件”。先限定测试场景，避免用一个材料的抽象‘净水值’包办全部效果。

订单应同时给出数量、可接受区间、测试条件、期限和奖励。缺少完全符合的货物时，可以明确报价后交替代品；精品判定使用可验证属性，不用未知性质虚发精品奖励。新材料可拿小批次参加试验，积累记录后才进入长期订单。

## 三、模拟地球：用区域变化控制工作量

第一版只做一颗可旋转的低模星球、6个试验区域、3种应用任务。区域是模拟与保存单位，远景只显示结果。禁止第一版同时开发全球气候、生物进化、人口经济和完整战争系统。

|阶段|主要交互|直接看到的变化|初期资产预算|
|---|---|---|---|
|熔岩→冷却|选择冷却/气体/水循环试验项目|发光裂缝变暗，蒸汽出现，凝结形成水面|同一球体的材质混合、蒸汽粒子、水层|
|海洋与生态|把适合当前条件的产品拖入试验区|污染斑块缩小，水色变化，海草/鱼群逐步出现|2类植被、2类生物、污染贴花|
|陆地与远古生命|完成生态条件与章节任务|苔藓→林地，少量程序化路径上的恐龙|复用地形，少量生物模型和动画|
|人类与工业|供应建材、净水设备和能源组件|聚落换外观，灯光亮起，烟雾减少，交通密度变化|每个时代替换建筑套件，不模拟每个居民|

时代是游戏章节和历史科普入口，不是“加水必然产生恐龙、人类”的演化预测。人类细分时代通过任务和区域改造逐步开放，保留前后快照与回看功能。工业、能源、环保先做；军事仅保留后续抽象防护/耐久应用方向，不挤占首版预算。

拖拽先显示落点轮廓和“预计影响区域”，释放后进入可取消的项目准备；消耗明确数量的工业产品后才开始部署。动画按项目进度逐步改变局部场景，短暂展示“水更清了”“夜间供电覆盖扩展”等结果，详细数值在点击区域后查看。颜色不能作为唯一反馈，同时改变模型、粒子和活动。

性能：可见区域使用MultiMesh植被、有限数量代表动物/车辆；区域逻辑1Hz更新，局部动画逐帧。离屏区域只保留状态。星球与浮岛不同时维持全部详细人物和建筑。先在中低端Android实机建立帧时间、内存和温升预算，再决定模型精度。

## 四、分子到物质，需要中间的工业产品层

不能把一个H₂O小球直接解释为一片海洋。产品链为：结构样品 → 确认配方与适用工艺 → 工厂消耗供料、能量和加工时间 → 输出有批次和数量的工业产品 → 星球区域项目。

第一批只做气体罐、水箱、通用过滤组件和太阳能组件中的少量配方。元素用量和化学计量单独列出；工业损耗、效率与游戏时间比例独立配置。H₂/O₂/CO₂不是在所有环境下都正向有益；环境条件和项目容量决定能否使用，不能无限投放同种气体刷生态等级。

太阳能组件应来自“经过验证的吸收层材料 + 电极/封装 + 工厂”，不把任何钙钛矿结构都直接变成高效电池。实际器件效果还取决于组成、结构、制造和工作条件。

## 五、未知材料与插值的科学边界

属性记录必须包含：结构指纹、相/结构族、属性名、数值与单位、温度/压力等条件、来源、方法版本、适用范围、不确定度和证据等级。金币评分独立存储，不能换个名字就当真实能量或带隙。

采用四级处理：

1. **有参考记录**：在组成、结构与条件匹配时展示来源值，明确实验值或计算值。
2. **同族范围内估计**：只对已验证的同结构族、固定条件、限定组分区间使用拟合或插值，展示估计区间。线性插值是可选模型，需要留出点检验误差；跨相变、跨结构族或区间外不继续外推。
3. **有适用计算模型**：模型覆盖当前元素、结构与性质时，生成带方法和验证误差的计算记录；超出范围转入“待验证”。机器学习势的原子力/势能能力不自动等于带隙或净水率预测能力。
4. **无可靠依据**：保留“性质未知”。仍可展示、收藏、参加创意展，或作为星球纪念雕塑。可在明确标为虚构规则的试验沙盘体验效果，但这份游戏效果不能写回真实材料属性库。

仅凭共价/离子半径与元素替换，无法得出任意材料全部物性。对已知相同结构族的混合物，也不能保证全部性质线性变化。因此建议先选一种属性、一族有端点与中间点数据的材料做小范围验证，再扩展体系。

上述四级是本项目的设计决策。依据包括：Materials Project按性质分别介绍计算方法；其电子结构文档明确列出常用DFT带隙的系统偏差与数值/解析限制，说明即使已有计算也不能当无误差实验值。NIST的数据评价指南强调材料数据质量的评价与使用场景。实际引入数据还需逐表核对许可、条件和方法，不能只复制一个数值。

- [Materials Project：各类材料性质的方法说明](https://docs.materialsproject.org/methodology/materials-methodology)
- [Materials Project：电子结构及带隙准确性](https://docs.materialsproject.org/methodology/materials-methodology/electronic-structure)
- [NIST：材料性质数据评价指南](https://www.nist.gov/publications/data-evaluation-theory-and-practice-materials-properties)

## 六、阶段验收与模块边界

近期先做浮岛：收集/装炉/补给闭环、商人与邮箱、分类工具箱、庭院收藏、存档兼容和移动端触控。下一次迭代以玩家实际试玩节奏调整价格、产速、爆率与来访间隔，再增加明确岗位分配、教授指导关系和建筑美术。

星球阶段先交付“水循环试验区”一个完整纵向样例：一个工业配方、一条生产线、一种产品、一个区域、三种可见状态和一个有来源的科普卡。验收包括资源不会凭空增加、失败有可读原因、未知材料不伪造属性、两种不同材料能够产生可解释的不同效果。之后复制数据和素材扩展其他应用。

保持模块单向依赖：MaterialCatalog/PropertyEvaluator → ResearchProjects与IndustrialRecipes → ProductInventory → PlanetRegionSimulation。渲染层读取快照，不直接修改钱包。订单和研究读取属性服务，不各自实现一套物性公式；实验结果按结构与方法版本缓存。前端只显示与玩家决策有关的信息，数据追溯收进科普档案。

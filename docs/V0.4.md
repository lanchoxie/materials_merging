# v0.4 真正的结构沙盒

0.4 把“替换一个模板位点”扩展为可以自己搭作品的工作台。玩家可以从一个 baseline 开始，也可以继续编辑自己的探索样品。

## 作品数据

`data/baselines.json` 是教学参考库，包含 H₂、O₂、N₂、CO₂、CH₄、NH₃、H₂O、HF、LiF 和 NaCl。每个条目保存元素顺序、坐标、连接关系、键级以及适用范围说明。距离是经过取整的参考或教学构造，不是势能、稳定性或物性预测。

新元素 N、F、Li、Na 与展示半径、颜色、来源分别记录在 `data/elements.json`；商店价格仍放在 `data/economy.json`，便于单独调经济数值。

## 编辑规则

`scripts/structure_sandbox.gd` 提供以下原子操作：

- `from_baseline()` / `new_structure()` 创建作品。
- `add_atom()` / `remove_atom()` 增删位点，最多 64 个原子。
- `set_position()` 调整位置，坐标限制在 ±20 Å。
- `toggle_bond()` 添加或移除 1–3 级连接，连接会在删除原子时自动重排索引。
- `formula()` 与 `complexity()` 生成展示用分子式和受上限保护的复杂度。
- `validate()` 拒绝未知元素、自连接、重复连接、越界坐标和超大作品。

改变组成或拓扑会清空 `baseline_id`，避免玩家修改后仍误用原结构卡片。只有重新匹配到有数据的参考体系，后续生产和收购系统才可以把作品作为已知结构处理；探索作品不会自动获得稳定性结论。

## 命名与复用

`LabState` 的 `save_sandbox_structure()`、`load_sandbox_structure()`、`list_sandbox_structures()` 和 `delete_sandbox_structure()` 使用当前平台的专用存档目录：桌面端是项目 `saves/structures`，安卓端是应用私有 `user://saves/structures`。名称仅允许单个安全文件名，单件作品限制 512 KiB；保存的是坐标、组成、连接、分子式和复杂度，读取时会把 JSON 数字规范回整数键级。

作品保存独立于生产存档，删除、覆盖和重新命名不会改变反应炉金币、库存或订单。这样可以先做一件创意作品，再把它复用到其他反应炉，而不会复制旧的库存和待收金币。

## 0.4 的科学边界

baseline 是“有说明的起点”，不是完整化学数据库。LiF、NaCl 当前是离子对教学样品，岩盐晶胞与周期边界会在后续晶体工作台补充。没有可靠参考的组合仍显示为探索作品；复杂度只用于游戏提示和任务排序，不等同真实能量。

## 检查

`tests/test_sandbox.gd` 覆盖 50 项检查：baseline 完整性、分子式、增删原子、连接增删与重排、边界拒绝、命名保存/读取/删除和作品库列举。
